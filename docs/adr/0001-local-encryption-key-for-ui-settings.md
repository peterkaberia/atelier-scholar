# Local file-based encryption key for Settings-UI API keys

API keys entered via the Settings UI are encrypted at rest (`core/secrets.py`, Fernet symmetric encryption) before being stored in the `SettingModel` SQLite table. The encryption key itself is generated on first run and persisted in a local file (`.atelier_secret.key`, gitignored) rather than a managed secrets service or a user-supplied passphrase. This was chosen over a full KMS/secrets-manager integration because Atelier is a local, single-user tool - a separate secrets service would add real operational weight (where does *that* system's credential live, how does it get provisioned) for a threat model where the key file already lives on the same machine, in the same trust boundary, as the SQLite DB it protects and the `.env` file it's meant to improve on.

**Consequences**: anyone with filesystem access to the project directory can decrypt the stored keys (same exposure `.env` already has today) - this protects against the keys leaking via git commits, DB file sharing, or casual inspection of the SQLite file, not against a compromised local machine. Rotating the key (deleting `.atelier_secret.key`) silently invalidates every previously stored setting; `core/secrets.py`'s `decrypt()` returns `""` rather than raising in that case, so a rotation just looks like "nothing is configured," not a crash.
